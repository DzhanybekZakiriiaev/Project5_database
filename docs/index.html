Project5 Database Module – Design Sprint #2 Executive Summary

1. Project Overview

The Database Team serves as the backbone of the enterprise system, providing persistent data storage and integration between the Facilities, Inventory, POS, HR, and Transaction teams. In Sprint #2, the primary goal was to implement version-controlled database migrations and integrate schemas received from the Facilities and Inventory Management teams.

2. Key Achievements

  • Implemented Flyway V3 migration to merge Facilities and Inventory schemas into PostgreSQL.
  • Resolved major configuration issues with database connection and Flyway path mapping.
  • Verified migration success via pgAdmin4 and Flyway logs.
  • Documented schema and migration progress with Doxygen auto-generated site.
  • Closed GitHub issue related to migration execution order.

3. Architecture & Integration

The current system runs on PostgreSQL 15 with the following integrated schemas:

  • public: Machines, Parts, Logs, Reports (Facilities)
  • inventory: Items, Stock_Levels, Stock_Ledger (Inventory Management)
